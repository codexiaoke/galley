# Galley 需求文档

> 状态：讨论稿，2026-11-12
> 项目名称：Galley。原意是印刷前交给编辑审阅的校样，对应本项目"Agent 写稿、站长审稿"的核心流程。

本文档汇总需求讨论中已经确定的结论。

---

## 1. 项目概述

### 1.1 一句话定位

一个由 Agent 运营、由站长把关的个人博客系统：内容以知识库的形式存储，文章和页面从知识库组装出来。

### 1.2 背景和目标

- 站长要做自媒体，需要一个个人博客，内容方向是面向程序员的 AI 内容，中文。
- 日常运营交给 Agent（首先是 Codex，通过 MCP 连接），站长负责审阅和提供个人素材。
- 项目以 MIT 协议开源，作为站长的个人作品。它必须能解决真实问题，不能是玩具。

### 1.3 要解决的真实问题

| 问题 | 本项目的回答 |
|---|---|
| AI 写的内容没有个人特色，谁都能写 | 素材箱加"观点""经历"类知识块，把站长本人装进知识库 |
| AI 内容的瓶颈是人的审阅时间 | 事实核实一次、处处复用；审阅成本随运营时间下降 |
| 技术内容几周就过期，旧文章悄悄变错 | 知识块变更沿引用关系传播，自动生成审阅任务 |
| Agent 有发布权限就可能出事 | 发布权由程序把关，不靠 Agent 自觉 |
| 内容组件化一直只有企业用得起 | 拆分和维护的负担交给 Agent，个人也能用 |

### 1.4 明确不做

- 不做向其他平台的分发（公众号、掘金等）。
- 不做公开评论系统。
- 不做多用户、多角色的账号体系，只有一个站长。
- 不做插件系统、主题市场、富文本拖拽编辑器。内置几套主题供站长选（见 5.13.5「前台主题」），但不做第三方主题的上传和分发：那要么在服务端执行外来代码，要么要维护一套长期稳定的样式接口，对一个个人站不划算。Galley 是开源的，想大改的人 fork 之后自己改，代码里为此留好了扩展点。
- 程序本身不调用任何大模型。

## 2. 设计原则

1. **人当主编，Agent 当编辑部。** Agent 负责选题、写稿、组装页面、维护知识库；站长负责审阅、批准和提供个人素材。
2. **内容是知识库，文章是组装结果。** 最小单位是知识块，不是文章。
3. **发布权限由程序管。** 默认任何 Agent 都不能让内容上线，只能提交审阅；站长可以对某一个 Agent 单独打开「直接上线」，默认关着、随时能收回，这样上线的内容会标出「没经过审阅」。关键在于这是站长的一次明确授权，而不是 Agent 自己能决定的事。
4. **程序不含智能。** 所有智能来自接入的 Agent。部署者不需要配置模型密钥，程序没有模型费用，也不绑定任何一家模型。
5. **不绑定 Agent。** 使用标准 MCP，任何支持 MCP 的 Agent 都能接入。
6. **不可信内容隔离。** 陌生人写的内容（留言）不给 Agent 读。
7. **数据不锁定。** 全站内容可导出为通用格式。
8. **为审阅疲劳设计。** 改动合并成批、已核实的内容不重复审、手机上能处理。

---

## 3. 角色

| 角色 | 说明 |
|---|---|
| 站长 | 唯一的管理员。登录后台，审稿、管理内容、投放素材、配置 MCP |
| Agent | 通过 MCP 连接的外部程序，首先支持 Codex。由定时任务触发，或站长手动叫它干活 |
| 读者 | 访问前台，阅读内容，可以给站长留言 |

调度不在程序里做：什么时候干活由 Agent 一侧的定时任务或站长手动触发决定。

## 4. 核心概念

### 4.1 知识块

知识库的最小单位。只把"硬内容"做成知识块，叙述性文字保持自由书写。

知识块的结构、引用语法、版本和变更传播的详细设计见[知识块、引用与变更集](design-knowledge-blocks.md)。

| 类型 | 说明 | 来源 |
|---|---|---|
| 事实 | 可核实的客观说法 | 外部来源链接 |
| 概念 | 术语和定义 | 外部来源或站长 |
| 代码 | 一段代码及其说明 | Agent 或站长 |
| 数据 | 一组用于图表或表格的数据 | 外部来源 |
| 观点 | 站长的判断和立场 | 站长本人 |
| 经历 | 站长亲手做过的事和结果 | 站长本人 |

每个知识块的属性：

- 内容、类型、标签
- 来源（事实类必填）
- 核实状态：待核实、已核实、已过期
- 核实日期
- 作者：哪个 Agent 或站长
- 可见性：公开或私密
- 版本历史
- 被哪些文章和页面引用

### 4.2 文章

文章由行文和对知识块的引用组成。知识块是被引用进来的，不是复制进来的。

### 4.3 页面

首页、关于页、专题页、概念页等，由组件组装而成，组件可以引用知识块和文章。

### 4.4 素材

站长投进素材箱的原始输入：想法、链接加评价、截图、踩坑记录。Agent 把素材整理成知识块和选题。

### 4.5 选题

一个待写的题目，放在选题池里，带优先级。

### 4.6 技能

存在程序里、通过 MCP 下发给 Agent 的运营说明，按任务拆分，Agent 用到哪个读哪个。技能由站长在后台编辑，带版本记录。任何 Agent 连接后读取技能，就知道该怎样运营这个站，不需要另外写提示词。

第一版包含的技能：

| 技能 | 内容 |
|---|---|
| 运营总览 | 每次运行的流程：先看待办，再按优先级处理 |
| 写作 | 站长的文风、结构习惯、禁忌 |
| 知识块整理 | 什么该做成知识块、怎么写来源、怎么查重 |
| 素材处理 | 怎样把素材变成知识块和选题 |
| 页面组装 | 组件怎么用、版面的规矩 |
| 修订 | 怎样处理批注和知识块变更带来的修订 |
| 选题 | 选题方向和判断标准 |

技能可以包含由程序生成的实时内容，比如页面组装技能里的组件清单来自当前组件库。

### 4.7 审阅卡片

看板上的一张卡片，代表一项等待站长处理的改动：一篇新文章、一次页面调整，或者一次知识块变更引起的批量修订。

## 5. 功能需求（第一版）

### 5.1 知识库

- 知识块的增删改查，支持六种类型。
- 全文搜索，Agent 写作前可以查询"站里已经确认了什么"。
- 查看任意知识块被哪些文章和页面引用。
- 公开与私密标记。引用了私密知识块的文章和页面无法发布，程序强制拦截。
- 新知识块随引用它的文章一起进入审阅；站长批准后标记为已核实。已核实的知识块在后续文章中不需要重复核实。

### 5.2 素材箱

- 站长在后台和手机上快速输入素材。
- Agent 通过 MCP 写入素材。典型场景：站长用 Codex 在别的项目里解决了问题，让它把过程摘要记进博客素材。
- 素材有"未处理"和"已处理"状态，记录它产生了哪些知识块和选题。
- 素材箱内容对 Agent 可读（它是站长自己的内容）。

**素材与选题的实现约定**（2026-11-12 实现并用真实的 Codex 跑通"素材 → 知识块 → 候选选题 → 采纳 → 成文"）：

- 素材可以标为私密。私密素材整理出的知识块一定是私密的，即使 Agent 传了公开也不行，所以不会出现在公开文章里。
- 知识块记录自己来自哪条素材。有产出的素材不能删除，只能归档。
- Agent 提出的选题是候选，站长采纳后才进入可写的队列；站长自己加的直接可写。写什么由站长决定，和"发布由站长把关"是同一个道理。
- Agent 领取选题时程序替它开好变更集并和选题关联：变更集批准后选题自动完成，撤回后选题回到队列。
- 一轮运营只写一篇，写优先级最高的。候选超过五个时 Agent 不再提新的。
- "素材已处理"和候选选题立刻生效，不属于变更集。知识块被打回时走正常的打回流程；站长想重来，在后台把素材放回未处理。

### 5.3 文章与页面组装

- 文章格式：Markdown 行文，加上知识块引用和组件标记。具体语法待设计。
- 组件库第一版包含：文章列表、精选卡片、图表、代码块、对比表、时间线、提示框、引用、专题入口。
- 组件库自我说明：Agent 通过 MCP 可以查到有哪些组件、每个组件的参数和适用场景。
- 组件库的实现情况（2026-11-12）：已有提示框（callout）、图表（chart）、时间线（timeline）、引文（quote，把一个知识块作为突出的引文）、文章卡片（post，站内另一篇已发布文章的标题、摘要和日期，那篇下线后卡片自动消失），代码块和对比表用 Markdown 自带的写法（已支持 GitHub 风格的表格）。还没有：文章列表、专题入口。
- 提交内容时程序做校验，返回具体错误，Agent 可以据此自行修正。
- 首页、关于页、专题页都由组件组装，Agent 可以新建页面或调整布局。
- 外观参数（颜色、字体、间距）可调，Agent 可以提出调整方案。
- 站长在后台也可以手动修改文章和页面。

### 5.4 工作流与看板

后台的界面和前台完全分开：左侧是菜单，右侧是内容；列表一律用表格，新建、编辑、确认删除一律用弹框。

后台的视觉参照 Notion 和飞书这类文档工具，因为它是每天要长时间使用的工具，耐看比抢眼重要：白底，几乎看不见的边框，内容直接排在页面上而不是套在卡片里，不用投影和色块堆层次；颜色只出现在标签和主按钮上；表格行内的操作平时是灰色，悬停才显出来。

后台首页是看板，按状态分列：

| 列 | 卡片来源 | 站长操作 |
|---|---|---|
| 选题池 | Agent 添加，或站长手动添加 | 增删、调整优先级、标记不写 |
| 写作中 | Agent 领取选题后 | 查看进度 |
| 待审 | Agent 提交审阅后 | 预览、批注、批准、打回 |
| 已打回 | 站长打回后 | 查看意见，等 Agent 修改 |
| 已发布 | 站长批准后 | 下线、查看数据 |

- 文章、页面改动、知识块变更引起的修订，都以卡片的形式进入看板。
- 看板顶部显示关键数字：待审数量、本周发布数量、近期访问量。
- 看板旁边显示 Agent 操作记录的时间线。
- Agent 只能把卡片推到"待审"，"待审"到"已发布"只有站长能操作。

### 5.5 审稿

- 预览效果与前台一致。
- 版本对比：显示本次提交相对上一版的改动。
- 行内批注：站长在具体位置写意见，Agent 下次运行时读取并逐条处理。

**审阅与直接修改的实现约定**（2026-11-12 实现，并用真实的 Codex 跑通"批注 → 打回 → 按批注修改并回复 → 重新提交"）：

- 站长直接修改已上线的文章或知识块：立即生效，不经审阅。程序替站长开一个变更集并当场批准，所以它和 Agent 的修改走同一套规则（引用校验、版本锁定、过期判定），也留下同样的版本记录。
- 修改知识块时站长要选"含义变了"还是"只是改措辞"：前者让引用它的文章进入 Agent 的待办，后者让文章自动跟到新版本。
- 文章正在某个未结束的改动里时，不能绕过它直接改。待审的稿子可以在那个改动里直接改，改完再批准。
- 批注针对变更集里某个版本的一段文字，记下原文和前后文来定位。打回后 Agent 要逐条修改并回复，还有批注没回复时不能重新提交；站长可以重新打开没改到位的批注。
- 打回时程序记下当时的正文。重新提交后，审阅页显示"相对上次打回时的改动"；修改已上线内容的，显示"相对线上版本的改动"。对比细到段落内部的字词。
- Agent 修改正文的一小段时用 `edit_document`（查找并替换，必须恰好命中一处），不必重交整篇；`save_document` 省略摘要表示不变。
- 批准、打回两种结论。
- 审阅界面标出文中引用的知识块及其核实状态；已核实的块可以略过，新增的块重点看。
- 后台在手机上可用，收到通知后能直接完成审阅。
- 每篇文章保留完整的修改历史和意见往来。

### 5.6 变更传播

- 一个知识块被修改时，程序找出所有引用它的文章和页面。
- 生成修订任务，Agent 重写受影响位置的行文。
- 所有受影响位置的改动合并成一张审阅卡片，站长一次看完。
- 知识块被标记为"已过期"时，引用它的已发布内容在后台被标出。

### 5.7 MCP 接口

> 下表中知识库和稿件两类工具已被[设计文档第 11 节](design-knowledge-blocks.md)的变更集方案取代，骨架已按新方案实现，以 `src/mcp/server.ts` 为准。素材和选题两类工具也已实现（2026-11-12），规则见下面的"素材与选题的实现约定"。数据一类已实现为 `get_analytics`、媒体一类已实现为 `upload_image`（2026-11-13），见下面的"访问数据"和"Agent 配图"。日志一类不做：运营日志已由变更集自动生成，不需要 Agent 自己写。

第一版工具清单（草案，名称待定）：

不提供的能力：下线、读取留言、直接修改技能、修改自身权限。发布默认也不提供，只有站长对某个 Agent 单独打开后才有（见 5.7 的"直接上线"）。

#### 直接上线

**实现情况**（2026-11-13）：站长可以对某一个 Agent 打开"直接上线"，它就能用 `publish_change_set` 让自己写的内容立即生效，不经过审阅。

- 为什么要有：站长自己在旁边用 Claude Code、Codex 这类 Agent 写稿时，人就在跟前，写完还要切到后台点一次批准，只是麻烦，并不增加把关。真正需要把关的是没人盯着的那种运行。
- 开关按 Agent 给，**默认关**，在后台的 Agent 页面上开和收回，随时可以收回。没有这个权限时调用 `publish_change_set` 会被拒绝，并提示去用 `submit_change_set`。
- 走的是和站长批准完全相同的那段代码（`approve`），引用校验、版本锁定、过期判定一字不差，区别只是记下一个"没经过审阅"的标记。
- 这样上线的内容在运营日志里显示为"直接上线"，站长事后照样看得到、可以下线。
- 下线、读留言、改自身权限始终不对 Agent 开放，这几条没有开关。

#### Agent 配图

`upload_image` 让 Agent 往媒体库传图片。这是 MCP 接口里第一个能写入站点资源的工具，所以口子收得很窄：

- **只收图片字节**（base64），不接受网址。程序不会替 Agent 去网上下载任何东西。
- 格式靠文件开头的字节判断，不信文件名和声明的类型；不支持 SVG（可以带脚本）；单张不超过 10 MB。这几条本来就有，Agent 和站长同一套。
- **一个 Agent 最多留下 10 张"传了没用上"的图片**，超过就不让再传。Agent 能传不能删，这条是防止写错循环或反复重传把磁盘堆满；用进文章里（哪怕只是还没提交的草稿）就不算在内，正常写稿碰不到。
- `alt` 必须填。
- 传上来的图片在后台的媒体库里标出是哪个 Agent 传的，站长在审阅预览里会和文章一起看到，不合适可以删掉。Agent 没有删除和改说明的权限。
- 技能里写明：只传自己做出来的图（截图、自己画的图表），不要传从网上找到的图片（版权不清楚），不要传含有私人信息的截图，能用正文组件讲清楚的不要配图。
- 这是只写工具，不在只读清单里，站长可以在后台关掉。

#### 访问数据

`get_analytics` 让 Agent 读访问数据，用来定选题，形成"写了什么 → 有没有人读 → 下一步写什么"的闭环。

- 只返回汇总数字：区间内的访客数和浏览量、和上一段同样长的时间相比的涨跌、读得最多的文章、发布超过一周却几乎没人读的文章、来源站点的域名、按分类和标签汇总的浏览量。
- 没有任何能对到具体某个读者的东西。访客标记每天换盐，过了当天就还原不了，所以访客数是"每天的访客数加起来"，跨天不去重；来源只存域名，不存路径和参数。
- 这是只读工具，站长可以在后台关掉。
- 技能里要求 Agent 提选题前先看一眼，同时写明数据少时不要过度解读。

#### 技能下发

技能通过四种方式提供，保证现有的 Agent 产品都能用上：

| 方式 | 做法 | 适用范围 |
|---|---|---|
| 官方技能扩展 | 按 MCP 的技能扩展规范，把技能作为资源提供 | 支持该扩展的 Agent |
| 工具方式 | 上表中的 list_skills 和 get_skill | 所有支持 MCP 的 Agent |
| 连接说明 | 连接时返回一段说明，引导 Agent 先读取运营总览技能 | 会读取连接说明的 Agent，包括 Codex |
| 导出安装 | 后台一键导出为标准技能文件夹，手动安装到 Agent 产品里 | 不通过 MCP 获取技能的场景 |
| 插件 | 把连接配置和入门技能打包成 Agent 产品的插件，见下文 | Codex，之后是 Claude Code |

MCP 的技能扩展在 2026 年 9 月定稿，目前属于测试阶段，支持它的 Agent 产品还不多，所以工具方式是第一版的主要途径。

#### Agent 插件

为 Agent 产品提供可导入的插件，导入后不需要手动配置就能运营站点。第一版先做 Codex 插件，Claude Code 插件使用同一份内容生成。

插件包含：

| 内容 | 说明 |
|---|---|
| MCP 连接配置 | 站点的 MCP 地址和认证方式，导入后 Agent 自动连接 |
| 入门技能 | 很薄的一层，只说明"这是什么、怎么开始"，并引导 Agent 从站点读取最新的技能 |
| 运营一次 | 一个可以直接调用的技能：读取待办并按优先级完成一轮运营 |
| 记到博客素材 | 一个在任何项目里都能调用的技能：把当前工作的摘要存进站点的素材箱 |

规则：

- **插件里的技能保持很薄，完整的技能以站点为准。** 插件是一次性导入的静态文件，站点上的技能随时会改，两边各存一份会不一致。
- **访问密钥不写进插件文件。** 插件从环境变量读取密钥，避免密钥随文件被分享或提交到代码仓库。
- **两种获取方式。** 开源仓库里提供通用插件，站点地址由使用者配置；每个站点的后台也可以生成一份预填好本站地址的插件供下载。
- 插件安装在 Agent 产品的全局位置，这样"记到博客素材"在站长的任何项目里都能用。

### 5.9 前台

- 首页、文章页、分类页、标签页、关于页。

- 字体使用读者电脑上已有的宋体，不下载网络字体。
- 阅读进度用页面顶部一条细线表示。
- 首页是单栏列表：顶部一行左边是网站名、右边是分类导航，下面文章一篇一行，每行是标题、摘要，右侧是日期和分类。版面紧凑，不留大片空白，也不放站点介绍之类的说明文字。
- 网站名是站长自己的名字（当前为"程序员小柯"）。Galley 是这套程序的名字，不出现在读者看到的页面上。
- 前台每个页面顶部都是同一行网站名和分类导航。
- 动画只用来说明发生了什么，幅度小、时间短：内容出现时轻微上浮淡入，列表各行依次出现；点进文章时列表里的标题移动放大成文章标题；切换分类时导航的红线滑到新位置；悬停时有颜色和位移的反馈。读者在系统里设置了"减少动态效果"时全部关闭。
- 文章有分类。分类由站长在后台创建，显示在首页的导航里，每个分类有自己的列表页；Agent 写文章时只能从已有的分类里选，新文章必须指定分类。
- 阅读区域的栏宽和字号随屏幕宽度一起放大，每行保持在四十个汉字以内。
- 阅读设置（2026-11-12）：文章页标题右上角一个很淡的"Aa"，点开可以选字号（小、中、大）和底色（跟随系统、纸色、深色）。选择存在读者自己的浏览器里，不发给服务器，之后浏览站里的其他页面也按这个来；页面打开前就用上，不会先闪一下默认的样子。后台不受影响。
- 每句话的依据用悬浮卡片显示，不用页边旁注。
- 阅读时不显示系统信息。文章页只有标题、日期和正文；每句话的依据在读者主动查看时以悬浮卡片出现。由哪个 Agent 撰写、经过几轮修改这类制作过程，放在运营日志页，不放在文章页。
- 留言表单。
- 站内搜索。
- RSS 和基础 SEO。

**实现情况**（2026-11-12）：

- 关于页（`/about`）：站长在后台"文章"页点"写关于页"来写，没写的时候这个网址返回 404，页脚里也不出现"关于"。前台目前只有这一个页面类的网址。

### 5.11 运营分析

后台的一个页面，保持简单：

- 内容数据：访问量趋势、每篇文章阅读数、热门文章、访问来源、各标签表现。
- Agent 运营数据：每周产出、一次通过和打回的比例、从选题到发布的平均耗时。
- 访问统计由程序自己记录，不接第三方服务，不使用 Cookie。

**实现情况**（2026-11-12）：

- 页面显示出来之后向站点自己的接口报告一次访问。只记首页、关于页、文章页和分类页。
- 同一位访客同一天看同一个页面只记一次。访客的标记是"当天的随机盐 + 地址 + 浏览器标识"的散列；盐每天更换且不保留，所以无法还原地址，也无法把同一个人在不同日子的访问关联起来。
- 自动程序（按浏览器标识识别）和站长自己登录后台时的访问不计数。
- 后台"运营分析"页：近 30 天每天的访客、看得最多的页面、来源网站、近 8 周每周上线的文章数、近 90 天的一次通过率、选题从提出到上线的平均天数。
- 各分类、各标签的阅读（2026-11-12 补上）：最近 30 天各分类、各标签下的文章一共被看了多少次。

| 主题 | 样子 |

### 5.13.6 相关文章

**实现情况**（2026-11-13）：文章末尾列出"讲到同样东西的"几篇，并写明共同讲到了哪些概念。

- 相关程度只看共同讲到的概念（正文里引用的概念块，加上正文里提到的术语），不看分类也不看标签：分类太粗，标签是人起的名字，同一件事常有好几种写法。概念来自知识库，是程序能对得上的。
- 引用过的概念分量更重：两边都引用算 3 分，一边引用算 2 分，都只是提到算 1 分。否则"示例文章里出现过一次"会排到真正在讲它的文章前面。
- 这一页上已经列出来的文章（系列目录、上一篇下一篇）不再推荐一次。
- 站里还没有概念块，或者这篇文章一个概念都没讲到时，这一节不出现。

### 5.13.7 幻灯片接口

**实现情况**（2026-11-14）：`/posts/<别名>/present.json` 返回一篇已发布文章拆成的幻灯片，给程序读。

- 每一页只有四项：序号、标题、所属小节、这一页的 Markdown 原文。
- **不返回 `:::notes`，也不返回场景动画里每一步的讲稿（`say`）。** 讲稿是作者演讲时自己看的提词，页面上不显示给读者，放进公开接口等于把它公开了。配音稿这类东西由用到它的工具自己生成，不是 Galley 的事。
- 做这个接口是因为拆页规则（每个二级标题一页、`---` 分页、一个大块一页、Mermaid 独占一页）只写在 Galley 这边，外部工具自己重写一份迟早跑偏。
- 未发布、已下线、不存在的文章一律 404。缓存五分钟。

### 5.13.8 场景动画

**实现情况**（2026-11-14）：正文里的 `:::scene`。之前的组件都是"一种内容一个做好的模板"（算法、代码演变、流程图），出了这几类就只能写字。场景动画是通用的：作者用一段 JavaScript 摆出画面上的东西（方块、圆、文字、代码、箭头、边界框），再写若干步，每一步里让它们出现、移动、变色、沿着连线发消息、推近镜头，配一句写给读者看的话。

- **代码只在服务端的沙箱里跑一次**，和 `:::trace` 用同一个 QuickJS：没有网络、文件、页面，时间和内存有上限。跑出来的是一份清单——每一步里"谁的哪个属性、在第几毫秒、用多久、变成多少"。读者的浏览器只拿这份清单播放，不执行作者的代码；清单本身也按格式再检查一遍，不直接相信沙箱里交出来的东西。
- **任意时刻的画面都能直接算出来**（`core/scene/frame.ts`，纯计算，不靠时钟）。所以同一份数据有三种用法：文章里滚到眼前自动播放，每步放完停够读那句文字的时间；演示里场景独占一页，方向键一步一步推进；打印和存 PDF 时显示最后的样子。以后导出视频要逐帧渲染、要按配音的时长卡每一步，也是从这里取画面。
- **每一步有两句话，是两回事**（2026-11-14 改正：第一版把它们当成了同一句）。`step("……")` 的那句是写给读者看的，显示在画面下面，是正文的一部分。`say("……")` 是讲稿：讲这一步时嘴上说的话，口语，演示里是字幕和演讲者的提词。写出来给人读的句子不能照着念，所以这两句意思一致、说法不同，技能里明确要求 Agent 不许照抄。
- **讲稿的待遇和 `:::notes` 一样**：文章页面上不带（交给播放器之前就去掉，不会送到读者的浏览器里），`present.json` 里也不带（从场景代码里整句摘掉）。为了摘得干净，`say()` 的括号里只能直接写一个字符串，用变量或拼接时保存会失败。没写讲稿的步骤，字幕退回去用那句文字。
- **颜色只能写主题变量的名字**（`ink`、`accent`、`c1` 到 `c5`……，可以加浓度），不能写具体的色值。画的时候才换成 `var(--…)`，三套主题和深色模式都不用另外处理。
- 一步里的动作默认一个接一个，`together` 里的同时开始；写在第一步之前的动作不是动画，而是一开始的样子。
- 保存时代码会实际运行，出错（包括写了不认识的选项、不认识的颜色）时保存失败并给出行号，Agent 可以照着改。
- **字幕的位置和分段**（2026-11-14）：字幕在画面最下方，开着字幕时每一页的内容给它让出位置，不再压在画面上。讲稿一说就是两三句，整段放上去会排成一大块，所以字幕一次只放一小段：按句子断开，太长的再按逗号断，横屏上每段正好一行（`render/captions.ts`），几段按各自的长短分摊这句讲稿的时间依次出现。这对页面的 `:::notes` 同样生效。有讲稿的步骤边放动画边讲，停留时间按说完这句话的时间估，不再是"动画放完再加阅读时间"。
- **画面的大小**（2026-11-14）：两处都是为了字看得清。一是镜头自动贴合内容：作者摆东西常常只用到舞台中间一块，四周空着，所以全景不按舞台取景，而是把整个过程里出现过的东西都量一遍，对准它们、放大到正好装下（最多 1.8 倍；摆出舞台外面的会退后装进来）。作者在第一步之前自己摆过镜头的，按作者的来。二是演示里有场景的那一页四周少留白，画面按"一页放得下的高度"取最大。竖屏画幅里横着排的场景仍然偏小；站长的视频只做横屏（2026-11-14 定），所以不为竖屏另做一套场景版式。
- **图片和自由绘图**（2026-11-14）：场景里可以放媒体库的图片（`image`），用 `spot` 按比例圈出图上的一块，配合镜头推近，一步看一处。场景里用到的图片和正文里的图片一样记入这篇文章的图片引用。自由绘图是 `path`：点由作者的代码算出来，折线、平滑曲线、封闭形状都行；`morph` 让一条线变成另一个形状（点数少的一边在最长的线段上补点，原来的顶点不动），`along` 让东西沿着线走，`animate` 让任意数值属性按作者给的函数变化。`axes` 建坐标系、画函数图像、把数学坐标换成舞台位置。这些都仍然是"代码在沙箱里跑一次、产出数据"：按函数变化的轨迹在沙箱里取好样（每 40 毫秒一个点），存成一串很短的匀速动作，读者的浏览器只是把它们连起来。
- **演示里只留字幕的位置**（2026-11-14）：视频的字幕由做视频的工具后期加（配音工具同时给出和声音对齐的字幕），所以演示有三种字幕状态：不显示、显示讲稿、只留位置。只留位置时画面不带字幕，每一页在底部空出 140（按 1600×900 的设计尺寸，约占高度的 16%），工具把字幕压上去不会盖住内容，也不用给视频加黑边。网址参数 `captions=space`，录制对话框里默认就是这一项；控制条上的"字幕"按钮（C 键）在显示和不显示之间切换。
- 上限：画面上 120 个东西（一条线最多 400 个点）、24 步、每步 900 个动作，运行 2 秒。
- 还没做：场景里的公式（LaTeX）；文字里引用知识块；读者可以拖动的参数；按配音时长对齐每一步；逐帧导出视频。

### 5.13.9 演示的转场

**实现情况**（2026-11-14）：之前换页是把上一页藏起来、下一页淡入，所有页一个样。现在转场按两页的关系选：

| 两页的关系 | 转场 |
|---|---|
| 同一节里翻页 | 上下接续，幅度小。上一页的大标题缩到左上角变成小字（或者小字留在原处不动），读者看得出"还在讲这一节" |
| 换了一节 | 左右推开，幅度大一些，看得出"讲下一件事了" |
| 进出封面和结尾 | 推近、拉远 |

- 往回翻时方向反过来。旧的一页先走，新的一页稍后跟上，两页的字不会叠在一起。
- 页内的内容（段落、列表、图）在新的一页进来之后依次浮上来；标题不参与，它要么随整页进来，要么从上一页移过来。
- **文字一条一条出现**：一页里的段落、引文、提示框、表格和列表的每一项，除了第一条都先藏着，按一下方向键出一条，出完才翻页；往回按原路退回。藏着的文字仍然占着位置，出现时版面不跳。以冒号结尾、后面紧跟着下一条文字的段落是引子，和下一条一起出现。代码、图和播放器一进这一页就在，不参与；页里有播放器时，按页面上的先后穿插（前面的文字先出，播放器走完自己的步骤，后面的文字再出）。顺序的规则在 `render/build.ts`。自动播放时每一条按自己的字数分摊这一页的时间。打印和存 PDF 时全部显示。
- **同类的大块接起来**：同一节里相邻两页都有同一类大块（都是代码块、都是图、都是播放器）时，这个大块不跟着整页走，而是从上一页的位置和大小变到这一页的，内容交叉淡入，看起来是同一个窗口换了内容。
- 用浏览器的视图过渡（View Transitions）做，和首页到文章页的"标题移动放大"是同一套机制：换页前后各拍一张，中间怎么动由 `globals.css` 里"演示的转场"一节决定。两页是什么关系由 `render/turn.ts` 判断，写在 `<html>` 的 `data-slide-turn` 和 `data-slide-dir` 上。
- 浏览器不支持、读者设置了减少动态效果、打印和存 PDF 时，直接换页。录制开始时回到封面不放转场。
- 还没做：相邻两页的代码块之间逐行对齐的变化（现在是整块交叉淡入；要逐行变化用 `:::code-steps`）。

### 5.14 备份和导出

- 全站一键导出：文章为 Markdown，知识块和其他数据为通用结构化格式。
- 定时自动备份。
- 支持从 Markdown 导入已有文章。

**实现情况**（2026-11-12）：

- 已实现完整备份：一个压缩包，里面是数据库的完整快照和媒体库的全部图片，在后台下载。备份进行时站点照常读写。
- 已实现恢复：在后台上传备份，替换现在的全部数据。先把备份解到临时目录检查，确认完好才动现有数据；现有数据不删除，挪到数据目录下的 `before-restore-<时间>` 里。
- 已实现导出：已发布的文章各一个 Markdown 文件（带标题、日期等信息头），知识块一个 JSON 文件。只给人看和给别的工具用，不能用来恢复。
- 已实现定时自动备份（2026-11-13）：每小时检查一次，最近一份超过一天就在数据目录的 `backups/` 里存一份，只留最近 7 份；停机后重启会补上。后台"备份与导出"页可以关掉、手动存一份、下载存着的备份。它和数据在同一台服务器上，只防改错删错，所以页面上提醒站长定期下载到别处。
- 还没做：从 Markdown 导入已有文章。

**部署相关的实现约定**（2026-11-12）：

- 站点设置（网站名、介绍、作者、网站地址）存在数据库里，后台可改。还可以写一段页脚文字（版权声明、备案号之类，最多 120 字）和一个链接，显示在前台每个页面最底部那行链接的下面，点击在新窗口打开；文字留空就不显示，链接留空就只显示文字。程序的默认站名是"我的博客"。
- 图片只能来自媒体库：站长上传，程序按文件内容识别格式（不支持 SVG），文件名由程序生成。正文引用外部图片或媒体库里没有的图片时不能保存。Agent 可以查看媒体库，不能上传。
- 文章或分类不存在时返回真正的 404 状态码：页面是边渲染边发送的，等渲染时才发现已经来不及改状态码，所以在渲染之前先查一次。
- 提供 RSS（`/feed.xml`，只含标题、摘要和链接）、站点地图（`/sitemap.xml`）和 `robots.txt`。链接的开头用站点设置里的网站地址，没填时用访问时的地址。
- 部署脚本 `deploy.sh`（2026-11-12）：第一次运行时问端口、域名、后台密码并写进 `.env`（权限 600），然后构建、启动、等健康检查通过，最后给出访问地址；本机防火墙开着时询问是否放行端口，并提醒云服务器要在安全组里放行。不填域名时直接开放端口；填了域名时加一个 Caddy 自动配置 HTTPS，Galley 的端口只绑在本机。另有 `update`、`status`、`logs`、`stop` 几个子命令。已在本机用 Docker 实际跑过一遍（端口 3456，非交互模式）。
- 本地构建上传（2026-11-13）：`release.sh 用户名@服务器地址` 在本机按服务器的处理器类型构建镜像，压缩后通过 ssh 传到服务器，只上传镜像和几个配置文件，然后在服务器上用 `deploy.sh` 启动，服务器不构建。用域名时 Caddy 的镜像也一并传过去。适合国内、小内存的服务器。本地构建默认用 npmmirror 和阿里云 Debian 源，可通过本机环境变量 `GALLEY_NPM_REGISTRY`、`GALLEY_APT_MIRROR` 覆盖，显式传空值则使用官方源；不读取本机 `.env`。在服务器上构建时可以选国内的 npm 和 apt 镜像源。
- 预构建镜像（2026-11-13）：GitHub Actions 在每次推送到 main 时先跑检查和测试，再在原生 x86 和 ARM 机器上构建，发布同时支持两种处理器的镜像到 `ghcr.io/codexiaoke/galley`（标签 `latest`、`sha-提交号`，打版本标签时还有版本号）。`deploy.sh` 默认通过毫秒镜像 `ghcr.1ms.run/codexiaoke/galley:latest` 加速下载，`GALLEY_IMAGE` 可指定其他地址，服务器不构建；`GALLEY_BUILD=1` 时才在服务器上构建。
- Docker 镜像里只有程序，数据在 `/data` 卷里。镜像构建时数据库是空的，所以前台任何读数据库的代码都不能在构建时执行（见 `AGENTS.md`）。
- 本地发布的 SSH 交互（2026-11-14）：`release.sh` 在构建和上传前完成 SSH 认证，后续检查、镜像与配置上传、远程启动共用本次连接，不保存密码。结束或中断时关闭连接并清理控制套接字；连接失效时直接失败，不在上传进度中重新弹出密码提示。

## 6. 权限与安全

| 规则 | 说明 |
|---|---|
| Agent 不能发布 | 发布和下线只存在于后台，MCP 接口里没有对应工具 |
| Agent 不能改自己的权限 | 工具开关和密钥只能由站长在后台管理 |
| Agent 不能读留言 | 留言是陌生人写的任意文字，可能包含操纵 Agent 的指令和他人的联系方式 |
| Agent 不能直接修改技能 | 只能提出修改建议，由站长批准后生效 |
| 技能只包含文字说明 | 不下发可执行脚本，避免在 Agent 的机器上运行远程代码 |
| 私密内容不外泄 | 引用了私密知识块的内容无法发布 |
| 密钥不明文保存 | 只保存校验值 |
| 所有 Agent 操作留痕 | 每次调用都有记录，可追溯 |
| 所有改动可回滚 | 文章、页面、知识块都有版本历史 |

已知局限：程序能拦住对私密知识块的直接引用，拦不住 Agent 把私密内容换个说法写进正文。这一层依靠站长审稿把关。

## 7. 非功能需求

- **部署**：一条命令启动，不需要额外安装数据库。
- **Agent 兼容性**：至少用 Codex 和 Claude Code 验证通过。Codex 已验证；它默认对未声明只读的工具要求人工批准，所以每个工具都要声明读写性质，接入配置里要把本站的工具设为直接放行，否则无人值守时无法运行。
- **手机端**：后台的看板、审稿、素材输入在手机上可用。
- **文档**：附带接入配置示例和一套默认技能。

### 7.1 技术选型

整个系统是一个程序、一个数据文件、一个容器。

| 部分 | 选择 | 理由 |
|---|---|---|
| 语言 | TypeScript，前后端统一 | MCP 官方开发包对它支持最好；一种语言降低贡献门槛 |
| 框架 | Next.js 加 React | 前台对搜索引擎友好，后台有重交互界面，MCP 需要 HTTP 接口，一个程序都能承担 |
| 数据库 | SQLite | 不用单独安装，备份就是复制一个文件，单人站点够用 |
| 数据访问 | Drizzle | 轻量，自带数据库结构迁移 |
| MCP | 官方 TypeScript 开发包，HTTP 方式，令牌认证 | Codex 和 Claude Code 都能连接 |
| 内容格式 | Markdown 加扩展标记，用 unified/remark 解析 | Agent 写 Markdown 最顺手；扩展标记用于引用知识块和插入组件 |
| 参数校验 | Zod | 同一份定义既校验 Agent 提交的内容，又生成给 Agent 看的组件说明 |
| 后台界面 | Tailwind 加 shadcn/ui | 成熟，手机适配省事 |
| 登录 | 自己实现的单管理员密码登录 | 只有一个用户，不引入完整的账号库 |
| 邮件 | 标准 SMTP，通过配置开启 | 不绑定邮件服务商 |
| 测试 | Vitest 加 Playwright | 重点覆盖权限把关、引用完整性、变更传播 |
| 部署 | 单个 Docker 容器，挂载一个数据目录 | 数据库、图片、备份都在这个目录里 |

具体版本在搭建骨架时对照各库的最新文档确定。

### 7.2 架构上的三个决定

1. **内容不用 MDX。** MDX 允许在文章里写代码并执行，Agent 写的内容不能有这个能力。只允许引用知识块和使用组件库里已有的组件。
2. **核心逻辑只写一份。** 权限规则、状态流转、引用关系放在一个核心层，后台界面和 MCP 工具都只是调用它，保证两边行为一致。
3. **用 SQLite 而不是 PostgreSQL。** 代价是不适合多人同时大量写入，而本项目是单人使用。

### 7.3 已知的技术风险

- **中文全文搜索**：SQLite 自带的全文搜索对中文分词支持一般。处理方式是使用三字符索引，并对两个字的短词做补充查询，不引入额外的搜索服务。
- **页面缓存刷新**：知识块更新后，引用它的页面都要刷新。引用关系表可以指出该刷新哪些页面，但这部分需要仔细设计。

## 9. 同类项目与差异

两轮调研的结论（基于搜索结果摘要，未逐个核实源码）：

| 项目 | 情况 | 与本项目的差别 |
|---|---|---|
| EmDash、WordPress、Grav、Strapi | 都有内置或官方 MCP 服务 | 把后台功能原样开放给 Agent，底层是文章表，审稿只是建议 |
| Ghost、Halo 的社区 MCP | 能创建、编辑、发布文章 | 同上 |
| vibecms | 给 Agent 用的博客系统，有草稿、版本、人工批准 | 仍是文章表结构 |
| LotsBlog、Superblog | 主打 Agent 运营博客 | 闭源商业产品 |
| Momentaj 的设计文章（2026 年 10 月） | 提出事实只存一次、页面由事实构建、审阅台为首页 | 只是设计；面向企业；没有变更传播和页面组装 |
| 企业技术文档系统（Tridion 等） | 内容组件复用，可查引用关系 | 企业级，为人工写作设计 |
| LLM Wiki 及其开源实现 | Agent 维护互相链接的知识库 | 私人笔记，没有发布和审稿，没有事实级引用 |
| Slite | 逐条核对说法，定期复查 | 闭源企业知识库 |
| FactWeave | 开源，由事实生成博客文章 | 单向生成，没有引用关系和传播 |

本项目的差异点：

1. 知识块变更沿引用关系传播，并自动生成合并的审阅卡片。
2. 知识库和页面组装是同一套结构。
3. 知识库里有站长本人的观点和经历，并区分公开与私密。
4. 面向个人、开源、自己部署、不绑定 Agent、程序不含模型。
