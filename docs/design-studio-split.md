# 博客和视频工坊的拆分

2026-11-16 起草。状态：设计，尚未实施。

## 为什么要拆

这两天连着做了四期视频（GraphRAG、Cordis、KV 缓存、LLM Wiki），碰到的麻烦大多出在博客和工坊的接缝上：

- 调一下封面停几秒、加一个录制用的转场，都要改博客的代码、发镜像、等站长部署，有一次连着部署了两轮。
- 只改了讲稿的生成规则，文章没变，工坊判断"来源没有变化"，同步不到新规则，只能手动给演示指纹的协议版本加一。
- 讲稿写在文章里：页的讲稿是 `:::notes`，步骤的讲稿是场景里的 `say()`。场景代码改一个字，这一步的编号就变了，镜头指向要重新绑，配音要重新对。
- 读者和观众要的东西不一样。issue #4 提出：不开演示时文章要写全，开演示时要以图形为主。为了出视频把文章压成"一页一句话"，读文章的人就吃亏了。这一条已经先做了（演示以图形为主、`:::present`，见 requirements 5.13.7）。

部署早就分开了：博客在服务器上，工坊用 `compose.studio.yml` 在站长电脑上单独跑，各有各的数据库。没分开的是代码、数据库表和职责。

## 一句话

博客只管文章：阅读版和演示版两种看法。工坊管把文章做成视频的一切，讲稿也归工坊。两边之间只过一份带版本号的"演示结构"，外加共享的界面零件。

## 职责

| | 博客 | 工坊 |
|---|---|---|
| 文章、知识块、引用 | ✓ | |
| 场景动画、演示页怎么画（含翻页动画） | ✓ | |
| 阅读版和演示版各显示什么（`:::article`、`:::present`） | ✓ | |
| 演示结构接口（有哪些页、每页哪些步、画面上写什么、动画至少放多久） | ✓ 提供 | 读取 |
| 讲稿（页的开场词、每一步的解说） | | ✓ |
| 镜头指向（指示、聚焦、放大） | | ✓ |
| 制片参数（每拍时长、封面结尾停多久、句后停顿、字幕切分） | | ✓ |
| 项目、版本、审查、配音、录制、导出 | | ✓ |
| 讲稿检查（开场和第一步重复、空段、多音字） | | ✓ |

判断一样东西归谁，就看它离开视频还有没有用：读者在博客上会看到、会用到的归博客，只为做视频存在的归工坊。

## 现状：缠在哪

1. **数据库表混在一起。** 工坊的 5 张表（`studio_projects`、`studio_revisions`、`studio_comments`、`studio_events`、`studio_connection`）定义在博客的 `src/core/db/schema.ts`，两边共用一套迁移。线上博客的库里有 5 张用不上的表，工坊的库里也建着博客全套的表。
2. **工坊的业务写在博客的核心层。** `src/core/studio-*.ts` 6 个文件（约 650 行）、`src/mcp/studio.ts`，以及 `src/core/tools.ts` 里 `surface: "studio"` 的十几个工具，博客自己一行都不用。
3. **工坊直接用博客内部的代码。** `integrations/video-studio/` 引用了 `src/core` 的数据库连接、Agent 密钥、权限、错误类型，以及 `src/app/admin/ui` 的界面零件。
4. **制片参数在博客里。** 每拍时长、封面结尾时长在 `src/render/narration.ts`，字幕切分和停留估算在 `src/render/captions.ts`，镜头指向在 `src/render/guide-*.ts` 和 `client/guide-focus.tsx`。
5. **讲稿在文章源码里，而且实际是公开的。** `:::notes` 和 `say()` 写在文章里。`present.json` 摘掉了它们，但公开的演示页（`posts/[slug]/present`）把每页的 notes 和场景的 say 都发给了浏览器：任何人打开演示页按 N 就能看到讲稿。这和"讲稿不公开"的规定不一致。
6. **拍点编号不稳定。** 页的编号是序号（`p1`、`p2`……），中间插一页，后面全部错位。步骤的编号是"场景代码的哈希.序号"，代码改一个字就全变了。场景元素的指向目标（`<哈希>:b18`）也跟着场景哈希变。工坊同步时按编号对讲稿，编号一变，讲稿和镜头指向就对不上了。

## 目标结构

同一个仓库，用 pnpm workspace 分包（待定 1）：

```text
apps/blog        现在的 src/：只有博客，不认识"项目、讲稿、配音、导出"
apps/studio      现在的 integrations/video-studio，加上 studio-* 核心模块、工坊的 MCP 工具、工坊自己的表和迁移
packages/contract  演示结构接口的类型、版本号、校验，两边都依赖它
packages/ui      后台和工坊共用的表格、弹框、选择器、样式（现在的 admin/ui.tsx、modal.tsx、select.tsx）
```

依赖方向只能是：两个应用依赖两个包，应用之间互不引用。用检查规则锁住：工坊引用博客内部文件时，`pnpm lint` 直接报错。

工坊的数据库只有工坊自己的表。Agent 密钥这类两边都要的东西，各管各的：工坊的密钥由工坊签发，不再借用博客的 `agents` 表。

## 演示结构接口

博客对工坊承诺的只有这一份数据，内部怎么实现是博客自己的事。

- **地址**：`/posts/<别名>/structure.json`，取代现在的 `narration.json`。里面不再有讲稿，所以可以公开，不需要密钥。
- **内容**：文章的标题、摘要，加上一串页。每页包括：
  - 页的锚点（见下节）、标题、所属小节；
  - 页上可以指向的正文元素（标题、段落、列表项）；
  - 页里的场景和步骤：每步的锚点、画面上那句写给读者的话、动画至少放多久、这一步画面上可以指向的元素。
- **版本**：接口格式有一个协议版本（`contract` 包里的常量，改格式时加一）；每篇文章的结构另有一个指纹，由文章内容、站点显示配置和渲染代码的构建号算出来，代码一变指纹就变，不再靠人记得手动加一。
- **未发布的版本**：`/admin/preview/<版本>/structure.json` 和对应的演示页，凭接入密钥读取。工坊可以先给未发布的版本出样片，满意了再上线。
- **录制控制**：演示页只暴露两件事：跳到某页某步，以及按工坊给的时长自动走。封面停多久、每步停多久、什么时候翻页，全由工坊通过参数传进来，博客不再有自己的默认时长。

## 讲稿归工坊

### 存在哪

讲稿是工坊项目版本的一部分，现在已经是这样存的（`studio_revisions.beats` 里每拍的 text 和 guides）。变化在于初稿的来源：以前从文章里抄过来，以后由 Agent 或站长在工坊里写。

### 怎么和步骤对上

编号按内容算，不按序号，也不按代码哈希：

- **页的锚点**：所属二级标题的文字，加上它在这一节里是第几页（同一节被拆成多页时）。小节标题不改，页就对得上。
- **场景的锚点**：页锚点加上它在页里是第几个场景。
- **步的锚点**：场景锚点加上这一步画面上那句话的指纹。那句话改了，再按"同一场景里的第几步"兜底。
- **场景元素的锚点**（镜头指向用）：场景锚点加上元素的文字（方块、文字的内容），没有文字的元素按类型和出现顺序。

同步时，工坊拿新结构逐个按锚点去对旧讲稿：
- 对上的：讲稿、指向原样保留。
- 只靠"第几步"兜底对上的：保留讲稿，但标成"请核对"。
- 新出现的：讲稿留空，进入审查。
- 消失的：讲稿收进这个版本的"已移除"列表，不悄悄丢掉，站长确认后再删。

配音照旧按讲稿文字的哈希复用，锚点怎么变都不影响已经配好的声音。

### 写作流程

1. Agent 用博客的写作技能写文章：正文写全，演示里要出现的句子用 `:::present` 标出来，场景只写 `step("……")`。
2. 文章上线（或者先做版本预览）后，在工坊建项目。工坊给每一拍附上画面上那句话和能指向的元素，Agent 照着画面逐拍写讲稿。
3. 工坊的检查：开场和第一步说同一句、空着的拍、讲稿里的多音字、第一拍时场景画面是空的。
4. 配音、录制、审查、定稿，流程不变。

写作技能跟着拆：博客的 `writing` 技能只讲怎么写文章；"按视频的模子写"里关于讲稿的那几条（第一句点题、不说两遍、避开多音字、每拍都写）移进工坊的制作技能。

## 制片参数归工坊

挪到工坊设置里，站长可以改，项目里也可以单独覆盖：

| 参数 | 现在在哪 | 默认值 |
|---|---|---|
| 封面、结尾停多久 | `narration.ts` 的 `TITLE_PAGE_MS` | 1 秒 |
| 一句话说完后留多久 | 工坊 `timing.js` | 350 毫秒 |
| 没有讲稿的页停多久 | `narration.ts`、`captions.ts` | 按字数估 |
| 字幕怎么切、每段多长 | `captions.ts` | 按句子、逗号切，一段一行 |
| 镜头指向的幅度和提前量 | `guide-motion.ts` | 最高 1.55 倍，提前约 450 毫秒 |

博客只在演示结构里给出"这一步的动画至少放多久"，这是画面本身的性质，不是制片的选择。

## 迁移步骤

每一步都能单独上线，上线后博客和工坊都照常能用。

1. **把工坊的代码和表搬走，不改行为。** 建 workspace；`studio-*` 模块、工坊的 MCP 工具、5 张表和迁移移进 `apps/studio`；界面零件抽成 `packages/ui`。博客加一个删除这 5 张表的迁移（线上表是空的）。工坊的数据库迁移要能接住已有的 `studio-data` 卷，四个已有项目原样保留。验收：两边测试通过，四个项目能打开、能再导出一次。
2. **搬制片参数。** 时长、字幕、镜头指向变成工坊的设置；博客的演示页去掉自己的默认时长，按工坊传进来的走。验收：只改封面时长，不部署博客，导出的视频封面就变了。
3. **演示结构接口和稳定锚点。** 新接口 `structure.json`（含版本预览），工坊改为按锚点同步。四个已有项目同步一次，讲稿和指向全部对上，配音全部复用。
4. **讲稿迁出文章。** 每篇文章里的 `:::notes` 和 `say()` 导出成对应工坊项目的初稿（还没有项目的文章就新建一个），然后从文章源码里删掉。博客解析时忽略这两样，保存时提示"讲稿已移到工坊"。公开演示页里的讲稿、提词和"显示讲稿"字幕随之移除，上面第 5 条的泄露也就没了。
5. **拆技能。** 写作技能和工坊的制作技能分开，工坊的检查上线。

## 取舍和风险

- **博客演示模式不再有讲稿。** 站长拿博客的演示模式现场讲课时，按 N 看提词、按 C 显示讲稿字幕的功能会没有了，需要在工坊里提供演讲者视图：打开演示页，旁边显示讲稿（待定 3）。
- **写场景时不能顺手写解说。** 讲稿要等文章写完再到工坊里写，多了一道工序。换来的是文章干净、讲稿可以单独改，改讲稿不用重新发布文章。
- **锚点也会对不上。** 小节标题改名、同一句话换了说法，锚点就失效了，只能靠兜底和人工核对。所以同步时宁可多标"请核对"，也不悄悄套用。
- **迁移期间两份讲稿。** 第 3 步到第 4 步之间，文章里和工坊里各有一份。规定以工坊为准，文章里的只在建项目时用作初稿。

## 待定

1. **仓库**：同一个仓库分包（建议），还是拆成两个仓库。站长一个人维护，同仓库可以一起发版，接口一改，一次检查就能测到两边；等有人只用工坊、不用博客时再拆。
2. **浏览器录屏按钮**（`render/client/recorder.ts`）：有了工坊以后，可以去掉；也可以留着，给不装工坊、只想快速录一段的站长用。
3. **演讲者提词**：同意挪进工坊，还是在博客里另外保留一份只给站长看的提词。
