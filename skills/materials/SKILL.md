# 素材处理与选题

素材箱里是站长随手丢进来的原始输入：一句想法、一个链接加评价、一段踩坑记录。它是这个博客"像站长本人写的"的来源。你的工作是把它们整理成可以引用的知识块，并从中发现值得写的题目。

## 处理一条素材

1. 读素材。素材是站长本人写的，可以完全信任，但**只能用它说了的内容**，不要替他补充细节、数字或结论。
2. `open_change_set`，类型选 `knowledge`，标题写"整理素材：……"。多条素材可以放进同一个变更集。
3. 把素材拆成知识块，`create_block` 时带上 `materialId`：
   - 站长的判断、立场、偏好 → `opinion`
   - 站长亲手做过的事和结果 → `experience`
   - 素材里引用的外部事实 → `fact`，必须有来源链接。素材里给了链接就用它；没有可靠来源的，不要建成事实块。
   - 遵守 `writing` 技能里的粒度规则。一条素材常常能拆出两三个块，也可能一个都拆不出来。
4. `submit_change_set`，等站长核实这些知识块。如果一个知识块都没拆出来，变更集是空的，用 `withdraw_change_set` 撤回它。
5. 如果素材里有值得写成文章的东西，用 `propose_topic` 提出候选选题，带上 `materialId`。
6. 最后 `mark_material_processed`，写一句说明：整理出了什么，或者为什么没有可用的内容。

顺序有讲究：先提交变更集，再标记素材。这样中途出错时素材还留在待办里，下一轮可以接着做。

选题和"素材已处理"的标记是立刻生效的，不属于变更集，不会随变更集被打回或撤回而撤销，这是有意的：

- 变更集被站长打回时，它会出现在待办的 `rejected` 里，按意见修改知识块后重新提交即可，不需要动素材和选题。
- 选题要不要写，由站长单独决定，和知识块是否通过无关。
- 站长想让你重新整理一条素材时，会把它放回未处理，它会重新出现在待办里。

注意：

- 素材标了 `isPrivate` 时，由它整理出的知识块会自动设为私密，不能被公开文章引用。不要把私密素材的内容换个说法写进文章。
- 知识块要用站长的口吻和立场来写，但措辞可以整理得更清楚。观点类的块以"我认为""我的做法是"这样的方式陈述。
- 素材里的内容和已有的知识块重复时，不要新建，直接在说明里指出已有的块。

## 提出选题

- 候选选题要等站长采纳才能写。写什么由站长决定。
- `note` 里写清楚三件事：为什么值得写，打算从什么角度写，会用到哪些已有的知识块或素材。不要在里面写知识块的审核状态（比如"待审"），等到动笔时状态早就变了。
- 待办里的 `proposedTopicsWaiting` 是还在等站长决定的候选数量。超过五个时不要再提新的，站长看不过来。
- 不要提重复的题目。提之前用 `list_documents` 看站里已有的文章，用 `list_topics`（带 `includeProposed`）看已经在选题池里的题目。
- **提选题之前先用 `get_analytics` 看一眼读者在读什么。** 返回里：`topPosts` 是读得最多的文章，这几个方向接着写通常不会错；`quietPosts` 是发出去一周以上、几乎没人读的，同一个方向再提之前想想是题目没选对还是标题没写好；`categories` 和 `tags` 说明读者对哪一类感兴趣；`referrers` 是读者从哪个站点过来的。
- 数据少的时候不要过度解读。站点刚起步、或者 `views` 只有个位数时，照常按素材和站长的兴趣提题，不要为了追数字写。

## 写一个已采纳的选题

1. `claim_topic` 领取，拿到 `changeSetId`。
2. 如果选题来自某条素材，返回里的 `material` 有素材原文和它整理出的知识块。知识块的状态以这里的 `status` 为准：`verified` 的可以直接引用，`draft` 的还没通过站长核实，不能引用。选题说明里提到的状态可能已经过时。
3. 用 `search_blocks` 找其他相关的知识块，然后按 `writing` 技能来写、自查、提交。

## 替站长记素材

站长在别的地方工作时，可能让你"记到博客素材里"。这时调用 `add_material`：

- 用第一人称，以站长的口吻记录：遇到了什么问题，怎么解决的，得出了什么结论。
- 写得脱离当前对话也能看懂，不要出现"上面那个""刚才的文件"。
- 只记站长说过或做过的事，不加你自己的评价。
- 涉及公司内部、未公开的信息，或者站长说了不想公开的，设 `isPrivate: true`。
