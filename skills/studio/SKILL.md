# 制作文章视频

Studio 是本机视频工坊，线上 Galley 提供文章与演示画面。工坊讲稿、配音、审查和成片独立保存，修改工坊讲稿不会改写文章。操作前用 `studio_get_skill` 读取当前制作要求。

## 接上当前项目

- 有项目 ID 时直接 `studio_get_project`；否则用 `studio_list_projects` 查找分配给自己的项目。读 `currentRevisionId`、`revision`、`comments` 和制作状态后接着做，避免重复创建项目。
- 确实要从另一篇文章新建时，先 `studio_list_articles` 取得真实 `slug`，再 `studio_create_project`。
- 每次修改或审查带刚读取的 `revisionId`，收到版本冲突先重读项目，保留别人的修改。待审版本不能编辑；用户要求返修时用 `studio_withdraw_review` 撤回相应阶段，再修改。
- 工坊使用自己的 Agent 密钥和 MCP 连接，通常是 `http://localhost:4321/mcp`。博客密钥、工坊 Agent 密钥和站长管理密钥是三种用途。没有 Studio 工具时，说明需要接入本机工坊；不要拿博客工具冒充，也不要读取 `.owner-key` 或调用站长管理接口绕过 Agent 权限。
- 工坊可由本机 Docker 运行，MCP 地址和制作流程不变。返回的 `/data` 是容器内路径，下载优先使用工具提供的 HTTP 地址；不要把容器路径当宿主机文件，也不要另建一个空工坊来找回项目。部署和迁移按仓库 `integrations/video-studio/README.md` 操作。

## 讲稿与视觉引导

在 `revision.beats` 读取逐拍内容，通过 `studio_update_narration` 批量提交实际需要的改动。`text` 是口语讲稿，接上前一句、说明画面变化，不逐字朗读页面。只改强调效果就只传 `guides`；不要顺带改声音或文章。

`guides` 绑定本拍 `targets` 中的真实 `targetId` 和讲稿原话 `phrase`，不用屏幕坐标、鼠标轨迹或自编 ID。目标要在讲到时实际可见；演示中隐藏的控件不能指向。原话应在该拍讲稿中唯一出现，多个指向按讲述顺序排列且不重叠。改稿时一起核对原话；要让效果停留整句，就绑定整句，不只填一个关键词。

| `emphasis` | 画面效果 | 适用情况 |
|---|---|---|
| `point` | 仅显示目标四角框 | 轻量标记、运动中的小目标 |
| `focus`（默认） | 四角框突出目标，弱化周围 | 普通讲解需要明确看哪里 |
| `zoom` | 聚焦并适度推近镜头 | 重点细节需要放大看清 |

当前样式不绘制辅助圆点、外圈或拖尾。优先选择与讲解相关的具体目标；概括、转场可不设指向，不要每句都放大。同一对象连续讲述尽量保持镜头，避免反复推拉。聚焦框和镜头会平滑切换，讲完回到全景；字幕保持原位，放大上限由渲染器控制，已有场景镜头也会计入目标大小。

`studio_update_narration` 参数示例（ID 必须替换为当前项目返回的值，原话替换为实际讲稿）：

```json
{
  "projectId": "<项目 ID>",
  "revisionId": "<当前版本 ID>",
  "edits": [{
    "id": "<拍点 ID>",
    "guides": [{ "targetId": "<本拍目标 ID>", "phrase": "讲到这个区域时的一段连续原话", "emphasis": "zoom" }]
  }],
  "note": "突出讲解区域并适度推近"
}
```

`guides: []` 清除该拍指向；`suggestedMs` 调整无配音时的停留时长。保存会生成新版本并重置审查。仅修改指向或强调方式时，原文未变的配音会复用；不需要强制重做全部配音。尚未配音的草稿按估时预览，有配音后根据真实字幕对齐，字幕段内按字数插值，不代表逐字强制对齐。

## 审查、配音和导出

1. 检查当前讲稿、指向和未回复批注。按 `beatId`、`timeMs` 或版本定位问题，修改后用 `studio_reply_comment` 逐条说明处理结果。无法落实的意见说清原因，不假装已改。
2. 普通权限用 `studio_submit_review(stage: "script")` 提交讲稿。用户已有直接定稿授权，且工具列表提供 `studio_publish_project` 时，可用它确认讲稿，不再额外索要同一授权；以工具返回的权限校验为准。若用户要求人工审查，仍走提交审查。
3. 讲稿通过后 `studio_generate_voices`，读取 `studio_get_project` 的 `revision.voiceJob` 等待结束。`failed` 时先处理具体错误；`forceIds` 仅用于确实需要重配的拍点。已有且匹配讲稿的声音直接复用。
4. 配音齐全后 `studio_render_video`，保留返回的导出 ID，用 `studio_get_export` 跟进。只有 `state: "done"` 才能交付文件；失败读错误、取消用 `studio_cancel_export`，不要把异步任务已受理说成已完成。
5. 审看这次真实 MP4 的画面和原声，确认讲述与聚焦一致、字幕清楚、镜头不裁掉重点、开头没有工坊占位提示和调试按钮。静帧只能验证局部画面，不能代替声音和镜头运动检查。无法实际播放时如实说明已验证与未验证的部分。
6. 用 `studio_submit_review(stage: "video")` 提交当前样片；具备上述授权且任务允许直接定稿时，用 `studio_publish_project(stage: "video", note: "具体检查结论")`。直接确认会标明未经人工审阅，不能声称站长已批准。通过后定稿的是同一文件，不重复渲染。

4K 导出由后台 Chromium 逐帧排版，再用 FFmpeg 编码为 3840×2160、30 fps 的 H.264/AAC MP4，并生成 SRT；不用共享标签页或屏幕录制，预览与导出共用聚焦逻辑。位图清晰度仍取决于原素材。`studio_get_export` 返回的文件路径相对于本机 Studio 地址，下载需该项目的访问身份；本机地址不是公开分享链接。

文章、引用或站点视觉变化导致来源版本不一致时，用 `studio_sync_source` 建立新版本，再核对拍点、讲稿与指向并重新审查。不要删掉版本参数、套用旧批准状态或覆盖历史成片。定稿只改变本机制作状态；发布线上文章、上传视频平台属于另一次明确授权的操作。
